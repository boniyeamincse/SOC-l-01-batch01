# Contributing Guide

Thank you for contributing to SOC Analyst Level 01 study notes.

This guide explains:
- How to add new notes
- How to update existing notes
- How to report note problems with GitHub Issues

## 1) Before You Start

- Keep content beginner friendly and accurate.
- Use clear headings and short paragraphs.
- Keep file names consistent with existing style.
- Do not delete someone else's content without clear reason.

## 2) Project Structure

- Main overview: README.md
- Class notes: classes/

Example files:
- classes/SOC_Analyst_Level_01_Class_01_Study_Notes.md
- classes/class-02.md

## 3) How to Add a New Class Note

1. Create a new markdown file inside classes/.
2. Use a clear file name, for example: class-03.md
3. Add proper title and sections in the file.
4. Update README.md class table:
   - Add new row for the class
   - Add note link
   - Add YouTube link or Coming soon

Suggested section format:
- Class title
- Topic summary
- Key concepts
- Practical examples
- Important terms
- Short recap

## 4) How to Improve Existing Notes

You can:
- Fix grammar and readability
- Correct technical mistakes
- Add missing explanation
- Improve examples
- Improve table formatting

Please keep edits focused. Avoid unrelated large rewrites in one change.

## 5) If You Find a Problem in Notes, Create an Issue

If a note has a problem, open a GitHub Issue.

Issue title examples:
- Class 02: Wrong explanation in SIEM architecture section
- Class 01: Typo in SOC core functions table

In issue description, include:
- Class and section name
- What is wrong
- Suggested correction
- Reference link if available

Use this quick template:

Title: [Class XX] Short problem summary

Description:
- File: classes/class-XX.md
- Section: <section name>
- Problem: <what is wrong>
- Suggested fix: <your fix>
- Reference: <optional URL>

## 6) Pull Request Guidelines

When submitting changes:
- Use a clear PR title
- Explain what changed and why
- Link related issue if there is one
- Keep one topic per PR when possible

PR checklist:
- Updated or added note file
- Updated README.md if new class was added
- Checked markdown formatting
- Verified links

## 7) Language Style

- Preferred: Simple English
- Optional: Bangla explanation in Roman Bangla if needed for clarity
- Keep terms consistent, for example: SOC, SIEM, alert triage, incident response

## 8) Code of Conduct (Simple)

- Be respectful
- Be constructive
- Focus on learning and accuracy

Thanks for helping improve this learning repository.
